Laravel: join() та select()

Основна вибірка даних з пов'язаних таблиць users та user_options (за полем user_id).

1. Базовий JOIN та SELECT

Метод join() об'єднує таблиці, а select() вказує конкретні поля для вибірки.

$user = DB::table('users')
    ->join('user_options', 'users.id', '=', 'user_options.user_id')
    ->select(
        'users.id',
        'users.name',
        'users.email',
        'user_options.phone',
        'user_options.address'
    )
    ->where('users.id', $id)
    ->first();

Результат: один об'єкт із вибраними полями:

$user->name;
$user->email;
$user->phone;
$user->address;

2. Отримання даних авторизованого користувача

Замість конкретного $id можна передавати ідентифікатор поточного користувача через auth()->id():

$user = DB::table('users')
    ->join('user_options', 'users.id', '=', 'user_options.user_id')
    ->select('users.*', 'user_options.phone', 'user_options.address')
    ->where('users.id', auth()->id())
    ->first();

3. Якщо додатковий запис може бути відсутній (LEFT JOIN)

Використовуйте leftJoin(), щоб отримати користувача навіть у тому випадку, якщо запису в user_options немає:

$user = DB::table('users')
    ->leftJoin('user_options', 'users.id', '=', 'user_options.user_id')
    ->select('users.*', 'user_options.phone', 'user_options.address')
    ->where('users.id', auth()->id())
    ->first();
Важливо: Якщо в обох таблицях є однакові назви колонок (наприклад, id), обов'язково явно вказуйте назву таблиці (users.id), щоб уникнути конфліктів і перезапису даних.

4. Альтернатива через Eloquent (без JOIN)

Якщо у моделі User налаштовано зв'язок hasOne() з user_options, вибірку можна спростити:

$user = User::with('options')->find(auth()->id());

// Доступ до даних:
$user->options->phone;
Порада: Варіант з Eloquent зручніший, якщо додаткові дані користувача часто використовуються окремо.
